# Feature / enhancement request template

Used for the `Enhancement requiring maintainer discussion` disposition: a real gap, with no existing contract violated, where the right next step is a conversation with maintainers, not a bug claim.

```markdown
## Summary

<One or two sentences: what's missing or could be better, and for whom.>

## Current behavior

<What happens today, factually, with a citation to where that's visible (code, docs, or observed behavior).>

## Motivating scenario

<A concrete situation where the current behavior is a real limitation. Prefer an observed gap found during exploration over a hypothetical.>

## Proposed direction (optional, clearly labeled as a suggestion)

<If offering one: a sketch, not a mandate. Make clear this is one possible approach, open to the maintainers' own judgment.>

## Alternatives considered

<Anything else that was considered and why it wasn't proposed instead, if relevant.>

## Additional context

<Links to related discussion/issues found during screening, if any.>
```

This is explicitly a discussion-starter, not a bug claim: never use bug-report severity language, and never imply the maintainers are obligated to accept the direction suggested.
